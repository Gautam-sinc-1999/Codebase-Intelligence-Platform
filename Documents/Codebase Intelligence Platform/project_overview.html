Codebase Intelligence & Conversational RAG Platform

A production-grade, AST-driven Developer Onboarding & Code Intelligence System powered by Graph RAG (Neo4j), Semantic Search (ChromaDB), Stateful Memory (MongoDB), and Groq LPU Acceleration.

Multi-Language AST Neo4j Cypher Graph ChromaDB Vector Store MongoDB 3-Tier Memory Groq LPU Engine

1. Executive Overview

When a developer joins a company or starts working on a new software project, understanding a codebase containing thousands of multi-language files (Python, Java, JavaScript, TypeScript, React JSX, SQL, YAML) is daunting. Generic document-based RAG systems fail because source code is structured, hierarchical, and interconnected rather than linear text.

📍 Where is it?

Locates exact code files, symbol definitions (classes, functions, components, API routes, database tables), and exact start/end line numbers without hallucination.

⚡ How does it work?

Traces end-to-end execution paths across Frontend Components ➔ API Clients ➔ HTTP Controllers ➔ Business Services ➔ Database Schemas.

🕸️ What depends on it?

Performs multi-hop graph traversals to identify caller functions, downstream callees, API handlers, and domain model dependencies.

🎯 What if I change it?

Executes reverse call-graph change impact analysis, highlighting confirmed callers, affected unit/integration tests, and secondary inferred impacts.

3. Phase 1: Repository Ingestion & Discovery

The ingestion pipeline recursively crawls uploaded software repository archives (`.zip`) or local workspace directories. It automatically ignores non-source directories, detects file encoding and programming languages, and skips binary blobs.

Ingestion Filters & Rule Policies

  • Ignored Directories: node_modules, .git, dist, build, target, venv, .venv, __pycache__, .pytest_cache.
  • Supported Extensions: .py, .java, .js, .ts, .jsx, .tsx, .sql, .json, .yaml, .md.
  • Binary Detection: Null-byte header checks prevent binary executable corruptions.
  • Content Hashing: SHA-256 hashes generated per file for version tracking and incremental indexing.

4. Phase 2: Code-Aware AST Syntax Parsing

Fixed-size token chunking destroys code semantics by splitting functions or classes in half. Instead, our platform utilizes syntax-aware AST (Abstract Syntax Tree) parsers to extract structured code entities preserving exact start and end line numbers.

// Sample CodeEntity Output JSON { "repository_id": "repo_123", "file_path": "backend/services/discount_service.py", "language": "python", "entity_type": "method", "symbol": "DiscountService.calculate_discount", "start_line": 18, "end_line": 35, "parent_symbol": "DiscountService", "imports": ["typing.Optional", "typing.Dict"], "calls": ["COUPON_DATABASE.upper", "max", "round"], "summary": "Method 'DiscountService.calculate_discount' in backend/services/discount_service.py (lines 18-35)." }

5. Phase 3: Neo4j Graph Database & Dependency Tracing

The platform constructs a Graph Knowledge Base using Neo4j (`neo4j` Cypher query driver). Nodes represent codebase symbols while directed edges model operational relationships.

Graph Node Label Description Sample Entities
File Physical source code file in repository Checkout.jsx, checkout_controller.py
Symbol / Method Class, function, or method entity DiscountService.calculate_discount
Endpoint HTTP REST API endpoint handler POST /api/checkout
DatabaseTable Database table or ORM model table:orders, table:users
// Cypher Query Example: Reverse Call Graph Traversal MATCH (caller:Symbol)-[r:CALLS]->(target:Symbol) WHERE toLower(target.name) CONTAINS toLower('calculate_discount') RETURN caller.name AS caller_symbol, target.name AS target_symbol, type(r) AS relationship, caller.file_path AS file_path, caller.start_line AS start_line

6. Phase 4: ChromaDB Vector Store & Hybrid Search

Semantic search alone can miss exact symbol matches (e.g. calculate_discount). We implement a 4-tier Hybrid Retrieval Strategy:

1. Vector Similarity (ChromaDB)

Embeds code snippets + symbols + summaries to retrieve conceptually relevant code.

2. BM25 Keyword Search

Tokenizes exact code text for matching variable names, error codes, and strings.

3. Exact Symbol Lookup

Scores exact matches on class names, function names, and API route paths.

4. Neo4j Neighborhood Expansion

Expands 1-hop dependencies around top candidate nodes to fetch full context.

7. Phase 5: LangGraph Agent Router & Groq LPU Reasoning

Every user prompt is classified into an intent badge by the QueryIntentClassifier:

  • FEATURE_EXPLANATION: Traces execution flow across components, controllers, and services.
  • CODE_LOCATION: Returns exact file paths, line ranges, and code snippets.
  • DEPENDENCY_ANALYSIS: Executes Cypher caller/callee traversals.
  • CHANGE_IMPACT: Analyzes primary target, callers, and test files.

When GROQ_API_KEY is set in .env, reasoning is offloaded to Groq's LPU hardware (`llama-3.3-70b-versatile`) delivering speeds over 500 tokens/second!

9. Phase 7: MongoDB 3-Tier Memory Architecture

The platform maintains a persistent conversational memory backed by MongoDB:

1. Short-Term Memory

Maintains recent turns for immediate conversational flow.

2. Working Memory

Tracks active state: current_feature, current_symbol, and relevant files.

3. Long-Term MongoDB Storage

Stores full chat threads, messages, and incremental summaries for resume chat.
